## Accepted trade-offs (11)

Known and kept, for the reason given.

- **SOURCE-001** (P2) Claude pending; full Kimi attachment unavailable. These missing sources remain explicit. No invented reviewer verdicts or reconstructed attachment.
- **ADAPTER-007** (P3) The managed Codex version link /opt/spaceapp/var/cli-versions/codex/current points at a missing 0.152.0, so the wrapper silently uses the legacy /usr/local/bin/codex (0.162.1). No functional impact: the fallback to the legacy binary is the wrapper's designed path and the canary verifies 0.162.1. Left unchanged at runtime; the next reviewed Codex promotion through cli-maintenance should install into the managed tree and repoint current.
- **EXT-C-F9** (P2) 400-day stateless sessions; the token's role stands when no user record exists. Single owner on loopback by default; revocation (logout, log out everywhere) is durable (SEC-011). Making a missing record least-privileged needs an audit of automation identities and the in-memory test store first.
- **EXT-C-F20** (P2) Core spawns opencode, which only the CLI image contains. The core image is at 1,023.5 of its 1,050 MiB budget; opencode stays in the CLI image. The Room Agent uses the Space Gateway or Gemini first; its OpenCode fallback returns no answer in public installs. Child processes no longer receive Space credentials (e851e2f128).
- **INT5-C-F2** (P2) Docker distribution: every agent can drive other panes through the pane-host socket and read all provider credentials. A public install has one owner and every pane is that owner's; the boundary is the CLI container, not the pane. Multi-user installs run one CLI container per user (core f5ad82792d, 3cb67847e9; launcher run-spaceapp 1.1.6, opt-in with user enable); per-pane isolation within one user stays a later release.
- **INT5-C-F15** (P3) Credential encryption is correct but fragmented; the database-password key has no AAD. Reviewer classed it a trade-off. HKDF-derived keys per purpose (fd98d0c7f5); a shared envelope with AAD is a later refactor.
- **INT5-C-F19** (P3) Public installs cannot scrape /metrics. Reviewer classed it a trade-off: /metrics is loopback or ADMIN only (EXT-C-F12); logs, /readyz and the healthcheck serve public installs.
- **INT5-C-F21** (P3) Host-side secret files are mode 0644 behind a 0700 directory. Containers read them as other uids (PostgreSQL as 999); the launcher creates the 0700 parent. Checking a pre-existing parent's mode is a 1.1.7 candidate.
- **INT5-C-F22** (P3) Shared writable memory is injected into agent instructions. One owner's agents share one memory by design; memory text is labelled untrusted in the instructions.
- **INT5-X-4** (P3) Recovery semantics are at-least-once. Non-idempotent provider calls are not replayed blindly; ambiguity is surfaced to the operator (recovery docs).
- **MU-005** (P3) An invite link can be claimed by whoever holds it for 7 days; the invitee's email is not verified. The owner sends the link to the person; it works once and can be revoked. Email verification needs outbound mail, which public installs do not have.

## Product decisions (3)

Scope choices, not defects.

- **FS-004** (P0) Host-root risk. Trusted single-owner ADMIN/OPERATOR mode is intentional. Preserve existing opt-in; authenticated UI indicator proof remains. 2026-10-11: SPACE_FILES_HOST_MODE (enabled|disabled, default enabled for the single-owner install) is a server-side switch; disabled rejects Admin Mode for every role with HOST_MODE_DISABLED. User Mode additionally never exposes .env files, secrets/, backups/, .git/ or var/ runtime data (managed worktrees excepted).
- **PRODUCT-001** (P2) Single-owner, multi-tenancy, HA and BSL limitations. Trusted self-hosted operator is declared scope. Multi-tenancy/Kubernetes/license changes excluded.
- **MU-006** (P3) An invite with the OPERATOR role gets owner-level access, including every room and the owner's CLI container. The operator's account model (plan step 3): OPERATOR is a trusted co-administrator; invite untrusted members as USER.
